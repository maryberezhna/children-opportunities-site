# Правила для сесій Claude у цьому репозиторії

## Не збирати сайт локально

`next build` на своєму компʼютері **не запускати**. Збірка — це ~1080 сторінок, і кожна ходить у **робочу** базу Supabase: тисячі запитів за кілька хвилин. 14.09.2026 кілька таких збірок (у тому числі від паралельних сесій) поклали API Supabase, і сайт показував «0 можливостей».

`next.config.js` сам зупиняє збірку поза Vercel. Якщо збірка справді потрібна — свідомо, одна, не паралельно з іншими сесіями:

```
ALLOW_LOCAL_BUILD=1 npm run build
```

Чим перевіряти замість збірки:
- `npm test` — тести й інваріанти;
- `npx next dev` у своєму worktree — сторінка в браузері (запити лише на відкриті сторінки);
- preview-збірка Vercel у PR — вона й є перевіркою збірки; мерж у main без зеленого Vercel неможливий.

## Після мерджу — перевірити, що продакшн справді розгорнувся

Зелений PR і мердж ще не означають, що зміна на сайті. 15.09.2026 мердж #300 не запустив продакшн-деплой Vercel: на сайті лишалась попередня версія, нова сторінка віддавала 404. Хуків деплою й Vercel CLI у репозиторії немає.

- Через 3–5 хвилин після мерджу звірити: `gh api repos/maryberezhna/children-opportunities-site/deployments?per_page=3` — має бути `Production` із SHA мердж-коміту.
- Відкрити саму зміну на dityam.com.ua (з `?c=<час>`, щоб не взяти кеш).
- Якщо продакшн-деплою немає — наступний мердж у main його запустить і забере все пропущене; або попросити Марію натиснути Redeploy у Vercel.

## PR, що не чіпає сайт, Vercel не збирає

З 21.09.2026 `vercel.json` → `scripts/vercel-ignore-build.mjs`: якщо змінено лише `scraper/`, `supabase/`, `tests/`, `.github/`, `scripts/` чи `*.md` у корені, збірку пропущено — і preview, і продакшн. За 9 днів вересня 74 зі 190 мерджів були саме такі, а кожна збірка — це гроші з місячного кредиту Vercel.

- Для такого PR відсутній продакшн-деплой — норма, не аварія. Перевіряти після мерджу треба лише PR, що змінили сайт.
- Сайт імпортує файл зі `scripts/` — допиши його в `SITE_SCRIPTS`, інакше впаде `tests/vercel-ignore-build.test.mjs`.
- Треба зібрати попри все — `[build]` у повідомленні коміту.

## Паралельні сесії

- Працювати у власному `git worktree`, не в головній теці репозиторію: чужий `next build` чи `git checkout` там ламає твій дев-сервер і стан файлів.
- Комітити лише свої файли поіменно — не `git add -A`: він підбирає чужу незакомічену роботу.

## Каталог і база

- Будь-яка вибірка «всі можливості» — через `publicOpportunities()` і `fetchAllRows()` з `lib/supabase.js`.
- На сторінках каталогу помилку бази не перетворювати на порожній список: `rowsOrThrow(...)`. Порожній каталог кешується на 5 хвилин і показується людям.
- Пропозицію, яку вносиш у `opportunity_suggestions` сам (від Марії чи з дослідження), пиши з `origin = 'maria'` або `'research'`. Контакт організатора — у `comment`, не в `contact`: `contact` — це той, хто приніс і кому відповідаємо листом. 20.09.2026 Facebook організації в `contact` адмінка показала як людину з поп-апа.
